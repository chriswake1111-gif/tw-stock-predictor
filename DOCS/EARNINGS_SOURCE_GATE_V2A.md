## Data Contract Changes

新增的是離線診斷格式 `mops-earnings-source-audit-v1`，不是正式研究或金融資料契約。每份輸出包含來源內容雜湊、文件期間、欄位定位及原始小數文字；數字保持十進位文字，避免浮點換算。

固定揭露 `calculation_eligible=false`、`value=null`、`historical_eligibility=not_asserted`。來源網址與觀測時間是呼叫端提供的取得紀錄，檔案雜湊不能驗證來源身分或公告時間，因此明示 `local_file_and_caller_receipt_not_authenticated`。報表合併／個別類型來自下載紀錄，並非離線文件身分驗證；工具不能作為正式匯入憑證。

僅接受已核對的基本／稀釋每股盈餘概念、台幣每股單位及數字轉換格式。未知轉換、公司不符、來源定位不符、期間異常、重複衝突與不合法 XML 均拒絕。XML 不載入外部結構定義或實體；來源中的腳本與指令只當資料。

無資料表遷移、無核准資格變更、無既有欄位或保存快照改寫。

## 重現方式

```powershell
python -X utf8 tools/audit_earnings_sources.py --manifest .tmp_earnings_v2_20260928/xbrl-sources-final.json
```

清單是最多 12 個物件的 JSON 陣列，每個物件包含 `path`、`symbol`、`year`、`quarter`、`url`、`observed_at`、`sha256`。檔案須位於清單同目錄；公司、年度、季別與觀測站下載網址須一致。讀取本機文件，不自動下載。

預設標準輸出為一個完整 JSON。需要保存稽核結果時加 `--output NEW_PATH`；已存在檔案一律拒絕覆寫。退出碼 `1` 代表成功完成稽核但來源資格未通過，`2` 代表輸入／完整性／輸出錯誤；本版不提供「合格」退出碼。

## Remaining Limitations 與下一個必要工程步驟

下一步需為完整財報附註建立經固定案例驗證的欄位對應，綁定「哪一期盈餘／哪一期加權平均股數／哪一版追溯調整」，並處理第四季只有全年報告時的合格來源或換算證據。不能讓助理傳入 `share_basis_verified=true`、由使用者勾選資料正確，或以期末股本替代加權平均股數。

這是來源與解析能力工作，不需要使用者挑數值。本次結果不能描述為過去十二個月獲利功能完成，也不能包裝成所有公司都可支援。正式頁面接入、保存指紋及技能更新仍在原核准第一批範圍內，但須先通過上述來源關卡。
