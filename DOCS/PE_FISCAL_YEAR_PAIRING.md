# EPS／PE 同年度配對

配對政策版本：`same_fiscal_year_v1`。此為 VAL-01／VAL-02／VAL-04 輸入適用性保護，未改乘法公式、證據分級、核准或撤銷權限，也不新增金融模型。

## 行為與契約

- 新建 PE 必須明確提供整數 `fiscal_year`（1900–2200）。本機表單、受限研究工具與管理匯入共用驗證。
- 只配對同一股票、同年度、當時可知且核准有效的 EPS 與個股 PE。不同來源仍各自呈現、不平均；產業／市場 PE 仍僅參考。
- `year_pairing` 回傳政策版本、`unmatched_eps_years`、`unbound_pe_ids` 及分項狀態。部分年度可算時保留結果，同時提示其他年度缺項；不把全頁遮蔽。
- 每個結果保留 `fiscal_year`、`pe_fiscal_year`、`pairing_policy_version`、來源版本與實際核准 ID。零／負 EPS 仍不適用；TTM 不冒充預估 EPS。
- 年度相符不代表幣別、拆股、基本／稀釋或盈餘口徑已一致，這些仍需選源時核對。本次不自動選取倍數或核准候選。
- `/api/ready` 與研究工具 `doctor`／`connect` 公開 `valuation_pairing_policy`。PE 預覽／草稿遇未支援的舊服務回傳 `pe_fiscal_year_upgrade_required`；其他唯讀研究功能保留。

## 舊資料與版本

遷移 `20260926_26_pe_fiscal_year` 僅新增 nullable 年度欄位，不推定、不回填。舊 PE、核准紀錄、指紋與已保存研究不變。舊請求以原冪等鍵重試可取回原紀錄，新請求缺年度則拒絕。

舊 PE 未指定年度，即使曾核准，也不再參與新的估值計算。使用者選定年度後，以「修改此版本」建立新版本，再自行核准；不移植舊核准。變更年度會取代同系列舊版本；要讓兩個年度持續各自有效，需明確建立不同系列。舊版仍可撤銷。

已保存的研究原文仍可讀取；**重新計算歷史切點**會遵守新配對政策，未綁年度的舊 PE 不產生結果。當時尚未建立／核准的新版不能回填到過去。政策或年度變動納入比較及保存內容指紋，不能沿用舊確認寫入變動後內容。

## 升級與回復

沿用啟動器升級前的 SQLite 備份機制與受檢查的遷移清單。發佈時必須攜帶新增 SQL，並更新研究工具及 Skill。開發測試只用隔離資料庫，不占用安裝版。

回復應停止測試實例後，使用 `EvidenceBackupService.restore` 將升級前備份還原到獨立路徑，再交給相容舊版驗證。不可直接刪欄位、改 checksum 或覆寫使用中的資料庫。回退到舊程式會失去本次跨年度保護，且回復點之後新增的研究不在舊備份中；新備份保留以供查核。

## 驗證範圍

焦點測試涵蓋：同年／跨年／部分配對、新舊 PE 年度驗證、版本變更與撤銷、歷史截止時間、舊冪等重試、遷移重跑、升級前後備份還原、已保存筆記不變，以及確認後內容改變時拒絕保存。前端驗證空白年度提示、既有紀錄修改、年度傳遞、改年度後重新預覽與部分結果呈現。

完整 Python 回歸、前端 test／lint／build 與 Skill 格式檢查須在交付前執行；安裝版覆蓋與實際使用者核准是另一次交付驗收，不能以單元測試代替。
