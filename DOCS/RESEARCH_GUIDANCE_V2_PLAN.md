## 三、Problem List（要解決的缺口）

1. 目前有逐季數字，卻沒有足夠證據確認跨季可比性。
2. 來源原值、公司修訂及不同報表期間必須分開，不能用最新資料冒充過去可知資料。
3. 有四筆數字不代表四個連續季度；單季、累計、基本與稀釋每股盈餘也不能混用。
4. 股數、幣別、合併範圍或修訂未釐清時，仍須保留逐季可讀資料及部分研究保存能力。

### 已閱讀的外部依據與限制

- [FinMind 官方文件原始碼：綜合損益表](https://raw.githubusercontent.com/FinMind/FinMind-Doc/master/docs/tutor/TaiwanMarket/Fundamental.md)：`EPS` 是單季原值，配股或分割可能使跨季股數基準不同。該文件的簡化淨利／股數示例不能直接推廣成所有公司的計算規則。
- [國際會計準則第 33 號：每股盈餘（IAS 33 Earnings per Share）官方概要](https://www.ifrs.org/issued-standards/list-of-standards/ias-33-earnings-per-share/)：計算涉及對應盈餘及加權平均股數；合併報表的盈餘須對應母公司普通股權益持有人。不能直接拿總淨利或期末股本代替。
- [臺灣證券交易所財務報告語言查詢說明](https://www.twse.com.tw/rwd/XBRL/show)：指出公開資訊觀測站的查詢管道。這只能支持來源探索方向，**尚未驗證可用於自動採集的端點、欄位完整性或歷史覆蓋率**。

以上檢閱日為 2026-09-28。FinMind 文件原始碼與發布網站的可讀內容有差異，實作應固定文件版本／雜湊，並用原始資料樣本核對。來源文件說明不是個別股票已通過驗證的證明。

## 四、Constraints（保留的邊界）

- 不以使用者勾選、助理閱讀完成或四季筆數取代資料核對。
- 不把歷史獲利改稱全年預估獲利（Forward Earnings per Share），不自動選用本益比（Price-to-Earnings Ratio）。
- 不新增自動核准、撤銷、正式研究保存或背景搜尋；原有使用者確認流程保持。
- 不更改既有杜金龍規則資格、估值公式、波浪公式或回測預設。新增計算若形成研究規則，必須另登錄穩定規則編號、來源及限制，不宣稱為已驗證的杜金龍核心。
- 不承諾所有股票都有完整資料。第一批以一般曆年制上市、上櫃普通股及已驗證報表格式為範圍；特殊會計年度、不同股權類別或未支援格式明示能力不足。
- 本機查證紀錄與金融事實維持隔離；助理整理稿不能直接升格成官方財報。
- 正式安裝替換、提交、推送及發布由本批開發驗收後另行處理。先前第一版發布授權不延伸到尚未完成的第二版。

## 五、Intervention Plan（第一批開發方案）

### 1. 先完成來源可行性關卡

固定少量公開樣本：至少一檔上市、一檔上櫃，以及一個配股／分割或財報修訂案例；昇達科可作上櫃候選，但不能先假定其資料合格。

核對季別、基本／稀釋類別、幣別、報表範圍、股數基準、修訂與實際可知時間。先以公司正式財報及公開資訊觀測站資料作核對依據，供應商資料保留原標示。

產出固定樣本清單、來源定位、取得方式、內容雜湊及逐欄可用性表；測試用數值採去識別固定案例。實際原始研究樣本保留本機，不夾帶私人研究資料進入提交。

**通過條件：** 至少一條可重現來源路徑能提供跨季核對所需證據。來源登入限制、反自動化限制、欄位缺失或證據矛盾均須記錄。不得繞過限制，也不能改成「預設股數未變」繼續實作可用結果。若未通過，交付可行性結果及具體缺口，暫不啟用合計功能。

### 2. 建立獨立、可追溯的獲利資料契約

優先沿用既有不可覆寫快照儲存，不為了第二版名稱就更動資料表。新標準化內容需明示：

| 欄位群組 | 必須回答的問題 |
|---|---|
| 公司與期間 | 哪家公司、哪段起訖日期、單季還是累計？ |
| 數字口徑 | 基本或稀釋、幣別與單位、合併或個別、對應哪類股東？ |
| 股數與修訂 | 使用哪個比較基準、依據在哪、是否已追溯調整、替代哪一版？ |
| 來源與時間 | 發布者、文件／頁碼／欄位定位、實際發布時間、首次觀測與匯入時間？ |
| 計算資格 | 哪些檢查通過、哪些缺失、能否供當前閱讀或歷史截止查詢使用？ |

以版本化解析器新增內容，舊快照原樣保留。缺實際公告時間時，以本機觀測時間限制可用範圍，不倒填季末或預設公告日。新取得的修訂不能改寫已保存研究，歷史資格也不因今天讀到資料自動成立。

若來源實證顯示必須新增資料表，須先補出具體新增式遷移與回復差異，再取得該變更核准；不在來源尚未確定時先建立通用財報資料庫。

### 3. 只計算有明確口徑的結果

- 第一批優先採用四個連續、同類型、可比且有證據的單季基本每股盈餘；保留所有輸入版本及檢查結果。
- 輸出明示「最近四季基本每股盈餘合計」及方法。四季已發布比率相加，不自動等同公司以全年加權平均股數計算的年度每股盈餘。
- 累計資料不得直接相減當成單季；只有來源契約及分母基準支持的換算才可納入。無足夠資料時保留缺項，不用近似值冒充。
- 不用期末股數代替期間加權平均股數，也不依股票代號、公司大小或「未查到公司行動」推定可比。
- 缺季、口徑不明、修訂衝突、股數證據不足分別回傳原因及空值；負值或零值是有效可能值，不當成缺資料。
- 合計不進入全年預估估值矩陣、不產生新的目標價，也不自動取得回測資格。

### 4. 接回原有介面與保存流程

沿用目前三層頁面，只在既有獲利區顯示結果、涵蓋期間、方法及來源。合格時移除對應缺項；不合格時顯示具體原因、責任及下一步，不新增填數字要求。

引導責任須依實際狀態判定：更新失敗交由程式、來源待查交由助理、未支援格式交由工程。資料有值不代表最新，更新失敗仍保留舊資料日期。

保存預覽固定本次獲利資料版本及缺項，沿用內容指紋與重送保護。資料在預覽後改變，先展示差異再確認；歷史研究仍唯讀，資料不足仍可保存部分研究。

預期影響：公開資料解析／服務、當前研究摘要、引導判定、既有財報顯示區、研究保存與工具輸出，以及兩份研究技能的相應說明。新增網路來源只接入既有受控採集路徑，不能讓分析引擎或助理整理文字觸發任意網址抓取。

### 5. 驗證、回復與完成標準

開發先使用隔離資料，功能開關預設關閉。既有表及研究內容做逐表／逐內容比對；切回第一版只關閉新能力、保留新快照，不刪表或覆蓋使用者資料。

| 驗證案例 | 預期結果 |
|---|---|
| 四季齊全且可比，含零值或單季虧損 | 程式正確合計，保留方法及每季版本 |
| 缺季、重複季、單季／累計混合 | 不計算，不借別季填補 |
| 基本／稀釋、幣別、報表範圍不同 | 不混加；顯示實際缺項 |
| 配股、分割、修訂、相互矛盾 | 舊值不覆寫；證據不足保持空值 |
| 季末早於公告、本機晚取得、歷史截止 | 不把未來或今天才取得的版本當成過去已知 |
| 更新失敗、舊解析器快照、格式變動 | 保留可讀內容與日期，不假裝新鮮或已驗證 |
| 保存途中資料變動、重送、回應遺失 | 不錯配、不重複保存，歷史內容不漂移 |
| 新能力關閉、舊研究讀回 | 第一版原有操作與證據邊界保持 |

執行焦點測試、完整 Python 回歸、前端測試、型別檢查、程式檢查、建置；再驗證 360、768、1024、1440 像素及鍵盤操作。套件與安裝版驗證於交付階段另外執行，不以原始碼測試代替。

第一批完成標準：至少有已核對的上市及上櫃公開案例能從來源追溯至正確結果，另有股數變動／修訂案例能正確計算或明確拒算；使用者仍可不填技術數字完成部分研究保存。若只完成固定案例測試、尚未取得合格公開樣本，應標示來源驗收未完成。
