# 自動波段資格檢查與隔離驗證第一版

本批只診斷本機資料及驗證既有轉折偵測的固定資料重播。不是自動判浪資格升格；正式自動候選維持關閉，人工候選、核准及保存契約不變。沒有新增金融公式、來源採集、公司行動還原、資料庫遷移或回測訊號。

## 使用方式與功能開關

個股「完整證據」→「資料狀態」中的「波段資料：現在能讀什麼」，顯示要求檢查區間、實際行情區間、主要下一步與處理責任。可展開六項檢查及證據，明確重新檢核。本功能在個股引導載入時唯讀取得資料；切換股票取消舊請求，沒有背景輪詢。候選頁提供前往該區塊的入口。

- `RESEARCH_WAVE_QUALIFICATION_ENABLED=true` 預設開啟；設為 `false` 回到原說明。
- 既有 `RESEARCH_WAVE_ASSIST_ENABLED=false` 仍關閉整體波段輔助。
- 歷史研究只顯示保存內容，不讀取目前資格覆寫歷史。
- 重新檢核不採集行情、不建立草稿、不核准、不保存，不改變研究確認指紋。

## 唯讀介面

`GET /api/v2/research/wave-qualification/{symbol}`，版本 `wave_qualification_v1`。沿用本機實例及標的檢查，回應與前端請求禁止快取。功能關閉只回傳版本、股票及 `enabled: false`。

使用既有資料庫 `mode=ro`、`query_only` 與單一讀取交易；不建立檔案或遷移。沿用最新截止時間可見價格快照選取與雙雜湊驗證，不因最新快照損壞退回舊版。要求區間取自快照既存來源定位，不改短區間。對來源網址僅解析及顯示純文字，絕不存取。

回傳股票、檢查時間、取得時間、快照識別與原始／標準化內容雜湊、要求與實際區間、六項檢查、更新與日期限制、責任和下一步。沒有完整行情、私人筆記或保存憑證。

| 項目 | 已確認的範圍與限制 |
|---|---|
| 來源與完整性 | 股票／市場識別、FinMind 來源綁定、解析版本與內容雜湊；第三方不冒稱官方。 |
| 價格基本品質 | 原始資料重新解析、標準化內容對帳、重複日期、有限正數、價位關係、整數成交股數、零量與排除列。結構合格不代表還原合格。 |
| 交易日與交易狀態 | 每日要求區間逐一核對官方日曆、上市及停復牌證據；不以平日推測開市，不跨市場替代，不把收盤價吻合當作最高／最低價驗證。沿用事件時間、撤銷規則。 |
| 價格比較基礎 | 現有未還原行情缺完整公司行動覆蓋，一律尚無證據；口徑聲明衝突則未通過。 |
| 資料可知時間 | 取得時間與行情日分離，缺逐筆公告／當時可用證據，不宣稱歷史可用。 |
| 轉折確認資格 | 只登錄專案實驗，隔離測試結果不升格正式資格。 |

單項狀態 `passed/failed/unknown` 對應「已確認／未通過／尚無證據」。整體狀態為 `insufficient_data`、`quality_warning` 或 `unavailable`，不提供整體合格分數。`automatic_candidates_eligible` 恆為 `false`。讀取／完整性失敗顯示「暫時無法檢查」，與缺快照分開。

每次最多檢查 5,000 筆、1,101 個日曆日；原始及標準化內容各上限 8 MiB。每項日期例子及證據參照至多 8 個，日期樣本文字上限 40 字；總數另列，超限不縮短區間以取得通過。

日曆參照採截止時間可見的最新修訂與最新來源修訂；撤銷、來源修訂後舊日曆、不同市場或不適格來源不復活為合格。上市或正常交易狀態缺證據時即使價格存在，完整性仍未知。日期精度不足時沿用現有保守事件可見規則。第一版未新增公司行動正向資格入口。

## 隔離工具

```powershell
python -B -X utf8 tools/audit_wave_qualification.py --db PATH_TO_EXISTING_DB --symbol 9911.TWO
python -B -X utf8 tools/audit_wave_qualification.py --fixture-manifest tests/fixtures/wave_pivots/manifest.json
```

預設只輸出結果。加上 `--output-dir NEW_DIRECTORY` 才寫入 `report.json` 和 `report.md`；要求新目錄，既有報告不覆寫。單份報告最多 1 MiB。結束碼：0 已完成診斷（**不是資格合格**），1 本機檢查不可用，2 輸入／檔案錯誤。無收藏掃描、連網或資料庫寫入。

真實資料模式只產生資格報告，本批不執行真實資料轉折重播。正向測試使用固定匿名合成資料清單，清單上限 16 KiB、8 份；每份上限 256 KiB／256 筆，路徑限清單目錄內，逐份核對原始檔案 SHA-256。Git 固定這些資料的 LF 換行，確保不同平台雜湊一致。

沿用 `WaveFibonacciEngine.detect_confirmed_pivots`，固定往前 5 筆、往後 3 筆，不呼叫整合推算。逐筆前綴重播核對「已確認結果不因後續資料改變」。相同高低價不冒認嚴格極值；同日雙向轉折標示順序不明；末端未滿確認筆數不輸出確認轉折。

輸出發生日、合成資料的確認日期、整份資料取得時間、資料雜湊、演算法與規則版本。合成資料日期只是重播序列，不是官方交易日證據；`known_at` 不回填成歷史確認日。`historical_availability: not_asserted`，`usable_as_anchor: false`。不進入候選、假設、核准、正式研究或回測資料表。

`PIVOT-EXP-01` 版本 1.0.0、證據 C、`project_operationalization: true`，只允許隔離診斷，不能描述為杜金龍已驗證核心。現有波浪及費波南希規則保持不變。

## 後續補強優先順序

1. **官方交易日及個股交易狀態覆蓋**：逐市場、逐要求區間保存開休市、上市及停復牌證據；先分清缺行情與缺證據，再補行情。不得靠縮短期間取得合格。
2. **公司行動與價格口徑**：建立完整覆蓋與「無事件」證據，再另批設計可追溯還原因子；減資、分割、除權息口徑不能混用。
3. **逐筆可用時間**：建立公開、取得與修訂時間證據，將固定快照重播和歷史當時可用性分開驗收。
4. **真實資料隔離重播**：前三項有合格樣本後，再核准固定資料集驗證既有偵測器；不調參追求報酬。
5. **正式候選另案**：通過上述資料及演算法驗證後，另提版本化候選契約、過期／撤銷規則與人工選用流程；不自動判第幾浪、核准或產生交易訊號。

本批先交付測試版本，安裝替換、提交、推送、發布另行授權。回復時關閉新資格旗標即可，無需刪表或還原研究資料。
